## 우선 수정 1 · [:50]과 [50:]가 반대

제출 셀 3:

```python
enc_sample = enc_text[:50]
```

이것은 **앞에서 50개 가져오기**다. 문제 요구는 앞의 50개를 건너뛰고 나머지를 사용하는 것이므로 다음이 맞다.

```python
enc_sample = enc_text[50:]
```

실제로 재실행해서 비교한 결과:

- 현재 x의 시작: `[40, 367, 2885, 1464]`
- 50개를 건너뛴 뒤의 시작: `[290, 4920, 2241, 287]`

**예시**: `[10,20,30,40,50]`에서 `[:2]`는 `[10,20]`, `[2:]`는 `[30,40,50]`이다.

이와 별개로 x와 y의 시작점을 한 칸 어긋나게 만든 부분은 정확했다.

## 우선 수정 2 · txt를 받아 놓고 다른 text를 사용

제출 셀 5:

```python
def create_dataloader_v1(txt, tokenizer, ...):
    dataset = GPTDataserV1(text, tokenizer, max_length, stride)
```

`txt`는 이 함수에 전달된 입력, `text`는 첫 번째 토큰화 문제에서 만든 짧은 전역 문자열이다. **함수 내부에서는 받은 txt를 사용**해야 한다.

```python
dataset = GPTDataserV1(txt, tokenizer, max_length, stride)
```

이 상태로 셀 6에서 txt=raw_text를 전달해도 실제 배치는 짧은 Hello 문자열로 만들어진다.

- 제출 첫 배치의 입력: `[[15496, 11, 466, 345]]` — Hello 문자열의 시작.
- 요청한 raw_text의 시작: `[40, 367, 2885, 1464]`.
- 다른 입력을 구분하는 고정 tokenizer로 추가 검사해도, 넘긴 txt가 아니라 전역 text를 읽는 것을 확인했다.

**예시**: `def 길이구하기(txt):`라고 받아 놓고 함수 안에서 예전 전역 변수 `text`의 길이를 계산하면, 새 문장을 전달해도 예전 문장 결과가 나온다.

tokenizer를 외부에서 받는 설계 자체가 틀린 것은 아니다. 다만 이번 문제는 함수 안에서 GPT-2 인코딩을 만들도록 지정했다. 위 전역 변수 버그와 인터페이스 차이를 구분한다.

## 정확하게 구현한 부분

- Dataset에서 입력과 target을 같은 길이로 자르고 다음 토큰으로 shift했다.
- 입력·정답을 텐서로 저장하고 같은 idx로 반환했다.
- 고정 토큰 9개, 길이 4, stride 2 검사를 추가로 실행했을 때 샘플 3개와 각 쌍이 정확했다. max_length=9에서 assert도 작동했다.
- 입력 `[2,3,5,1]`의 임베딩 표는 `(6,3)`, 조회 결과는 `(4,3)`이었다.
- 마지막 셀은 helper를 거치지 않고 Dataset에 raw_text를 직접 전달했으므로 올바른 원문을 사용했다. 이 부분은 함수 버그와 별개로 평가했다.
- 마지막 셀의 실제 shape: 입력·정답 `(8,4)`, 토큰 임베딩 `(8,4,256)`, 위치 임베딩 `(4,256)`, 합산 `(8,4,256)`.

`GPTDataserV1`은 요구 이름 `GPTDatasetV1`의 오탈자지만, 정의와 호출에서 같은 이름을 써서 실행은 됐다. 전부 같은 이름으로 수정한다. Python 3.12에서는 제출 첫 셀의 f-string 안팎에 같은 큰따옴표를 사용한 것이 문법 오류는 아니다. import는 `import importlib.metadata`로 명시하면 의존 관계가 더 분명해진다.

## 재시험: 답을 보지 않고 다음 세 가지부터

1. **슬라이싱**: 리스트 `[10,20,30,40,50,60]`에서 앞 2개를 버린 결과를 변수에 담고 출력한다. `[:2]`와의 차이를 말한다.
2. **함수 인자**: DataLoader 함수를 고친 뒤 서로 다른 두 입력 문자열로 호출한다. 각 배치의 첫 입력이 정말 전달한 문자열의 토큰에서 나온 것인지 확인한다. 전체 정답을 베끼기보다 문제의 txt 전달부터 수정한다.
3. **배치**: 기존 문제 8의 고정 텐서로 batch_size=2에서 drop_last=False/True의 배치 수·shape를 먼저 예측하고 실행한다.

이후 seed·검사 코드를 보완하고 새 커널에서 전체 실행한 노트북을 다시 제출한다. 정답 수정만이 아니라 “왜 잘못된 데이터가 들어갔는지”를 설명하면 이해도를 추가 확인한다.
