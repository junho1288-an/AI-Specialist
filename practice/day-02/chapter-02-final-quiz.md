## 문제 5 · GPTDatasetV1 클래스 직접 만들기 [20점]

**사용할 라이브러리:** `torch`, `torch.utils.data.Dataset`.

**인터페이스 요구:** 클래스 이름은 `GPTDatasetV1`, 생성자는 `txt`, `tokenizer`, `max_length`, `stride`를 받는다.

**만들 것:** 샘플을 생성·보관하고 번호로 꺼낼 수 있는 Dataset 클래스.

**순서**

1. `Dataset`을 상속한다.
2. 객체 내부에 입력 샘플과 정답 샘플을 각각 보관할 리스트를 만든다. 이름은 `self.input_ids`, `self.target_ids`로 한다.
3. 전체 텍스트를 토큰 ID로 바꾼다. `<|endoftext|>`를 특수 토큰으로 허용한다.
4. 길이 `max_length`의 입력과 그다음 토큰 정답을 만들 만큼 토큰이 있는지 `assert`로 확인한다. 실패 메시지도 적는다.
5. 시작 위치를 0부터 `stride`만큼 이동하며 완전한 입력·정답 쌍을 만든다. 다음 토큰 정답까지 원본 안에 있어야 한다.
6. 각 조각을 정수 텐서로 바꿔 두 리스트에 같은 순서로 추가한다.
7. `__len__`에서 저장한 샘플 수를 반환한다.
8. `__getitem__`에서 요청한 `idx`의 입력·정답 한 쌍을 반환한다.

**검증용 도구 — 이 부분은 복사해도 된다. 실제 BPE가 아니라 자르기 로직 확인용이다.**

```python
class FixedTokenizer:
    def encode(self, txt, allowed_special=None):
        return [10, 20, 30, 40, 50, 60, 70, 80, 90]
```

**완성 후 직접 해볼 검사**

- txt에는 아무 문자열, tokenizer에는 위 도구의 객체, max_length=4, stride=2를 넣어 Dataset을 만든다.
- 샘플 수, 0번·1번·마지막 샘플의 입력과 정답을 출력한다.
- 각 텐서 길이가 4인지 확인한다. 각 정답이 해당 입력의 다음 토큰인지 원본과 대조한다.
- max_length를 9로 바꿨을 때 지정한 `AssertionError`가 나는지 별도 검사한다. 의도한 예외는 잡아서 기록하고 이후 문제를 진행한다.

**말로 설명:** `i`와 `idx`는 어떻게 다른가? `__getitem__`에서 정답의 idx까지 한 칸 이동하면 왜 안 되는가?

## 문제 10 · 위치 정보까지 더해 모델 입력 만들기 [10점]

**지정값**

| 항목 | 값 |
| --- | --- |
| 텍스트 | 문제 3의 raw_text |
| 어휘 크기 | 50257 |
| 임베딩 차원 | 256 |
| batch_size | 8 |
| max_length | 4 |
| stride | 4 |
| shuffle | False |
| drop_last | True |
| num_workers | 0 |

**순서**
