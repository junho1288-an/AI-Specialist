셀 번호는 파일 위에서부터 센 순서입니다. 자체 연습 문제이며 실제 출제 범위는 강사 공지를 따릅니다.

Chapter 4 목차이전확인 문제복습 카드

1. Chapter 3의 통합 헤드 구현 재사용

입력(B,T,d_in)
→
Q·K·V + 헤드 분리(B,H,T,head_dim)
→
마스크 Attention(B,H,T,T) 가중치
→
헤드 결합 + out_proj(B,T,d_out)

여기서 d_out은 전체 출력 크기입니다. 이 셀에는 원래 빈칸이 없으며, Chapter 3 통합 구현 수업과 같은 원리를 복습합니다.

예시: 입력 (2,4,8), 전체 출력 8, 헤드 2개면 헤드당 4차원입니다. 점수 shape는 (2,2,4,4), 최종 출력은 (2,4,8)입니다.

2. GPT에서 필요한 이유

각 위치의 입력 벡터는 다른 허용된 위치의 정보를 모아 문맥이 반영된 벡터로 바뀝니다. 뒤쪽 답을 미리 읽지 않도록 causal mask를 적용합니다.

attn_scores = queries @ keys.transpose(2, 3)
attn_scores.masked_fill_(mask_bool, -torch.inf)
attn_weights = torch.softmax(
    attn_scores / keys.shape[-1]**0.5, dim=-1
)
context_vec = (attn_weights @ values).transpose(1, 2)
scores는 비교 점수, softmax 후 weights는 참고 비율, weights @ values는 정보의 가중합입니다. Attention weights와 최종 GPT의 어휘별 다음 토큰 점수를 구분하세요.

context_length는 미리 만든 마스크의 최대 길이입니다. 실제 입력 T는 이를 넘지 않아야 합니다. dropout 전 softmax 행 합은 1이며, 훈련 중 dropout 후에는 항상 1이라고 보장되지 않습니다.

시도 후 셀 2 전체 완성 코드 보기
class MultiHeadAttention(nn.Module):
    """
    멀티 헤드 셀프 어텐션 (Multi-Head Self-Attention) 모듈입니다.
    입력 데이터 간의 관계성을 여러 관점(Head)에서 병렬로 학습합니다.
    """
    def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
        super().__init__()
        assert d_out % num_heads == 0, "출력 차원(d_out)은 헤드 수(num_heads)로 나누어 떨어져야 합니다."

        self.d_out = d_out
        self.num_heads = num_heads
        self.head_dim = d_out // num_heads  # 각 헤드가 담당할 차원 크기

        self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

        self.out_proj = nn.Linear(d_out, d_out)
        self.dropout = nn.Dropout(dropout)

        self.register_buffer("mask", torch.triu(torch.ones(context_length, context_length), diagonal=1))

    def forward(self, x):
        b, num_tokens, d_in = x.shape # b: 배치 크기, num_tokens: 시퀀스 길이

        keys = self.W_key(x)     # Shape: (b, num_tokens, d_out)
        queries = self.W_query(x)
        values = self.W_value(x)

        keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
        values = values.view(b, num_tokens, self.num_heads, self.head_dim)
        queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

        keys = keys.transpose(1, 2)
        queries = queries.transpose(1, 2)
        values = values.transpose(1, 2)

        attn_scores = queries @ keys.transpose(2, 3)  # 결과 Shape: (b, num_heads, num_tokens, num_tokens)

        mask_bool = self.mask.bool()[:num_tokens, :num_tokens]
        attn_scores.masked_fill_(mask_bool, -torch.inf)

        attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
        attn_weights = self.dropout(attn_weights)

        context_vec = (attn_weights @ values).transpose(1, 2)

        context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)

        context_vec = self.out_proj(context_vec)

        return context_vec

01 · 헤드당 크기

전체 8차원, 헤드 2개면 head_dim은?

시도 후 정답·해설

4. 8/2=4입니다.

02 · 미래 가리기

attn_scores.masked_fill_(mask_bool, ????)

시도 후 정답·해설

-torch.inf. 예: 미래 점수를 -∞로 만들면 softmax 뒤 0입니다.

03 · 최종 정보

context = attn_weights @ ????

시도 후 정답·해설

values. Value 벡터들을 참고 비율대로 섞습니다.

04 · 출력 축

입력 (2,4,8), d_out=8이면 출력 마지막 차원은?

시도 후 정답·해설

8. 통합 구현의 d_out은 최종 전체 출력 차원입니다.

05 · 미래 누설

“미래 토큰만 바꾸면 앞 위치의 출력도 반드시 바뀐다.”

시도 후 정답·해설

X. 인과 마스크가 올바르면 앞 위치는 미래 토큰을 참고하지 않습니다.

06 · 내 말로 설명

왜 sqrt(d_out)이 아니라 sqrt(head_dim)으로 점수를 나누나요?

작성 후 비교할 해설

각 헤드에서 Q·K가 실제 비교하는 벡터의 길이가 head_dim이기 때문입니다. 예: 전체 8·헤드 2면 비교는 각 4차원에서 이뤄집니다.
