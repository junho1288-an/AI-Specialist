03 / 같은 입력을 세 역할로 변환Q·K는 찾기 위해, V는 가져오기 위해

Q = Query · 질의

현재 위치에서 찾는 특징.

비유: “이런 책이 필요해.”

K = Key · 검색 단서

각 위치가 매칭에 내놓는 특징.

비유: 책의 검색용 색인.

V = Value · 전달할 정보

참고 비율에 따라 실제로 가져올 내용.

비유: 책에서 가져오는 내용.

모든 토큰이 Q·K·V를 하나씩 가집니다. Q 전용 단어와 K 전용 단어가 따로 있는 것이 아닙니다. Self-Attention(자기 어텐션)은 세 가지를 같은 입력 시퀀스에서 만듭니다.

queries = self.W_query(x)   # nn.Linear(3, 2)
keys    = self.W_key(x)     # 별개의 nn.Linear(3, 2)
values  = self.W_value(x)   # 별개의 nn.Linear(3, 2)

한 토큰의 3개 숫자를 서로 다른 방식으로 조합해 각각 2개 숫자로 만듭니다。가중치 표는 W_query, W_key, W_value의 세 개입니다. 토큰 6개 각각을 W_query에 넣으면 Q 6개, 같은 토큰 6개 각각을 W_key에 넣으면 K 6개, W_value에 넣으면 V 6개가 나옵니다. 각 표는 모든 토큰에 공유됩니다. 코드의 nn.Linear는 x @ weight.T + bias입니다. 이 예시는 bias=False입니다.

“각각의 행렬” = 서로 다른 세 가지 숫자 조합법

아래 숫자는 계산을 쉽게 만든 보충 예시입니다. 입력 x=[1,2,3]을 세 표에 똑같이 넣습니다. 각 표의 한 행과 x를 곱해 더하면 출력 숫자 하나가 됩니다.

W_query = [[1,0,0],     Q = [1×1+2×0+3×0,
           [0,1,1]]          1×0+2×1+3×1] = [1,5]

W_key   = [[0,1,0],     K = [2,4]
           [1,0,1]]

W_value = [[1,1,0],     V = [3,3]
           [0,0,1]]

같은 입력인데 조합에 쓰는 숫자들이 달라 Q·K·V가 달라집니다. 다음 토큰 x=[4,5,6]에도 이 세 표를 그대로 사용하면 Q=[4,11], K=[5,10], V=[9,6]입니다. 토큰마다 표를 새로 만드는 것이 아닙니다.

세 표는 처음에 각각 초기화되고 학습 중 갱신됩니다. 단어마다 별도의 W가 있는 것은 아닙니다.

왜 그냥 x끼리 비교하고 x를 가져오지 않나요?

그렇게 만든 단순 Attention도 계산은 가능합니다. 다만 Q·K·V를 나누면 “찾는 기준”, “매칭용 단서”, “전달할 내용”을 각각 학습할 수 있습니다. xᵢ·xⱼ는 대칭이지만, qᵢ·kⱼ와 qⱼ·kᵢ는 서로 다를 수 있습니다. 역할 분리로 표현의 자유도가 커집니다.

교안 109쪽의 “항상 자기 자신을 우선 주목”은 일반 법칙으로 외우지 마세요. 내적 크기는 벡터의 길이에도 영향을 받으므로 자기 점수가 항상 가장 큰 것은 아닙니다.

교안 108~112쪽·Chapter 3 셀 1. API: PyTorch Linear. “검색”은 이해를 위한 비유이며 외부 검색이나 RAG를 실행한다는 뜻은 아닙니다.

04 / 교안의 실제 숫자를 눌러 보기한 토큰의 Q로 모든 K를 비교합니다

처음에는 journey에 집중하세요. 그 위치가 Your와 자기 자신을 얼마나 참고하는지 봅니다. 숫자는 셀 1의 레이어 선언 순서와 manual_seed(123)을 그대로 재현한 PyTorch 2.5.1 결과입니다. 아직 학습하지 않은 랜덤 모델이므로 의미 있는 문법 관계를 찾은 결과는 아닙니다.

지금 보는 위치: journey

데이터 불러오는 중…

각 3차원 x → 각 2차원 Q·K·V. 토큰 개수 6은 줄지 않습니다.

① Q · K = 관련성 원점수

현재 Q와 Your의 K를 비교하는 내적 하나:

같은 일을 K 6개에 반복한 원점수 행:
한 행은 “지금 선택한 토큰이 다른 각 위치를 보는 점수”입니다. Q @ K.T는 이 계산을 6개 Q 모두에 한꺼번에 합니다.


② 미래 가리기 → 스케일 조절 → 비율 만들기
체크를 해제하면 미래를 볼 수 있는 비교용 계산입니다. GPT 학습에는 체크된 상태가 필요합니다. journey는 Your·journey까지만 볼 수 있습니다.
점수 / √2 → softmax → 아래 참고 비율
√2는 Q·K의 차원 수가 2이기 때문입니다. 차원이 커질 때 점수가 너무 커져 softmax가 극단적으로 쏠리는 경향을 줄입니다.
softmax는 상대적 비율로 바꿉니다. 0점도 비율 0이 되는 것은 아닙니다. -∞로 가린 점수는 비율 0이 됩니다.


③ 비율 × V = 새 문맥 벡터
이것이 Attention의 직접 출력입니다. 단어도 ID도 아니고, 가져온 정보를 섞은 2개 숫자입니다. journey의 새 벡터도 여전히 journey 위치에 놓입니다.


실험: Your의 V만 바꾸면?
Q·K를 고정하고 V만 바꾸면 위 참고 비율은 그대로, 출력 벡터는 바뀝니다. 즉 어디를 얼마나 볼지는 Q·K가, 가져올 내용은 V가 담당합니다. 이 조작은 역할을 분리해 보는 실험이며 W_value 학습 자체를 재현한 것은 아닙니다.


④ 모든 토큰의 참고 비율을 모으면 Attention Map


대표 계산: Your·journey가 아래 표의 숫자가 되기까지
이 예시는 미래 차단 ON·V 배율 1의 고정 계산입니다. 위 조작을 바꿔도 이 설명의 숫자는 유지됩니다. 표와 비교할 때 미래 차단을 켜 주세요. 소수는 반올림해 표시했습니다.

√2의 2는 Q·K 벡터의 길이입니다. QKᵀ 점수 행렬은 (6,6)이지만 √6으로 나누는 것이 아닙니다. Q·K는 각각 토큰당 2개 숫자이므로 d_k=2입니다.

Map은 “섞을 비율”, z는 “그 비율로 섞은 결과 벡터”입니다.

자기 자신이어도 Q와 K는 서로 다른 벡터입니다. 같은 입력을 서로 다른 W로 바꿨기 때문입니다. 내적은 자기 자신일 때 1이 되는 공식이 아니며, 이 계산은 정규화된 코사인 유사도도 아닙니다.
journey→Your의 0.483이 높게 보이는 주된 이유는 선택지가 두 개이고 두 점수가 비슷하기 때문입니다. 실제로는 자기 자신 0.517보다 낮고 거의 반반입니다. 허용된 점수가 모두 같으면 대상 하나일 때 1, 둘이면 0.5씩, 셋이면 약 0.333씩입니다. 서로 다른 행의 비율은 후보 수까지 고려해서 읽어야 합니다.
현재 W는 학습 전 랜덤값입니다. 따라서 이 숫자만 보고 “journey가 Your와 의미상 강하게 연결된다”고 설명할 수는 없습니다. 학습을 통해 Q·K의 매칭이 예측에 도움이 되도록 조정됩니다. V는 정해진 비율로 실제 전달할 정보이며 이 Map 비율 계산에는 들어가지 않습니다.

색은 각 지도의 값 크기를 나타냅니다. ①·②는 각 지도 내 크기, ③은 0~1 비율 기준이므로 다른 지도끼리 색 농도로 수치를 직접 비교하지 마세요. 정확한 값은 숫자로 비교하고, 마우스를 올리면 소수 6자리까지 볼 수 있습니다.


① S = QKᵀ → ② softmax 입력 = mask(S) / √2 → ③ A = softmax(②) → Z = A @ V


journey → Your 칸을 따라가면 0.166 → 0.117 → 0.483입니다. Your → journey 칸은 0.348 → −∞ → 0으로 변합니다. ③의 비율로 V를 섞으면 (6,2) 문맥 벡터가 되므로, V를 곱한 뒤 결과는 토큰×토큰 지도가 아닙니다.


③을 크게 보기 · 기존 Attention Map
행: 누가 참고하는가(Q) / 열: 누구를 참고하는가(K·V). 숫자는 softmax 후 비율입니다. 점수 행렬과 비율 행렬은 둘 다 (6,6)이지만 값과 의미가 다릅니다. 오른쪽 위의 미래 위치는 차단됩니다.


숫자를 간단히 줄이면: V₁=[10,0], V₂=[0,10]이고 비율이 [0.8,0.2]라면 새 벡터는 [8,2]입니다. 더 많이 참고한 V₁의 성분이 더 많이 들어옵니다. 이는 위 랜덤 계산과 별개의 보충 예시입니다.

05 / 이름과 shape를 연결하기점수·비율·출력은 서로 다릅니다
scores · 원점수Q @ Kᵀ
(6,6)
→

(6,6)
→
context_vec · 새 벡터weights @ V
(6,2)
V는 (6,2)이므로 (6,6) @ (6,2) = (6,2). 중간의 6끼리 합쳐져 토큰 정보를 섞습니다. (6,6)은 다음 단어 6개의 확률이 아닙니다.
셀 1 코드뜻배치 포함 shape
queries = self.W_query(x)각 위치의 찾는 기준(2,6,3) → (2,6,2)
queries @ keys.transpose(1,2)각 Q가 모든 K와 비교(2,6,2) @ (2,2,6) → (2,6,6)
masked_fill_(mask, -torch.inf)미래 열 가리기(2,6,6)
torch.softmax(scores / √2, dim=-1)각 행에서 참고 비율 만들기(2,6,6)
attn_weights @ values각 행의 비율로 V들 섞기(2,6,6) @ (2,6,2) → (2,6,2)
dim=-1은 마지막 축, 여기서는 “참고할 대상 6개” 방향입니다. 배치 두 개는 서로 섞이지 않고 각각 계산됩니다.

Attention이 직접 “step”이라는 단어를 출력하지는 않습니다. 뒤의 블록과 출력층이 이 벡터를 이용해 어휘 전체의 점수를 만듭니다. 이 연결은 Chapter 4에서 구현합니다. 실제 GPT에서는 블록 폭을 맞추고 residual·FFN 등을 함께 사용하며, Chapter 3의 작은 d_out=2 예시를 그대로 전체 GPT라고 보면 안 됩니다.
