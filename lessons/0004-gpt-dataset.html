class GPTDatasetV1(Dataset):은 PyTorch의 Dataset을 상속해 우리 데이터셋의 동작을 정의한다는 뜻입니다. class 셀을 실행하면 설계가 정의되고, dataset = GPTDatasetV1(...)을 실행할 때 샘플이 만들어집니다.

2. max_length는 폭, stride는 이동 간격

max_length는 샘플 하나의 토큰 개수, stride는 다음 샘플의 시작점으로 움직이는 칸 수입니다. 두 값 모두 양의 정수를 사용합니다.

token_ids = [10,20,30,40,50,60,70,80,90]
max_length = 4
stride = 2

for i in range(0, len(token_ids) - max_length, stride):
    input_chunk = token_ids[i:i + max_length]
    target_chunk = token_ids[i + 1:i + max_length + 1]
샘플 길이 4, 시작점을 2칸씩 이동한 예시
샘플 번호 idx원본 시작점 i입력 x정답 y

12[30,40,50,60][40,50,60,70]
24[50,60,70,80][60,70,80,90]
stride와 정답의 +1은 다른 역할입니다.
stride는 샘플과 샘플 사이의 시작 간격입니다. 정답의 +1은 같은 샘플 안에서 다음 토큰을 가리킵니다. stride가 2여도 정답은 한 칸 뒤입니다.

고정된 연습용 토큰 ID에 교안의 range·슬라이싱 규칙을 적용한 그림입니다. Python·PyTorch를 실행하는 것은 아닙니다.

왜 range의 끝은 전체 길이 − max_length일까요?

원본이 9토큰, max_length가 4라면 range(0, 5, 2)이므로 시작점은 0·2·4입니다. 끝값 5는 포함하지 않습니다. 입력 4개뿐 아니라 그다음 정답 토큰까지 필요하기 때문입니다.

3. 완성 코드에 역할을 붙여 보기

import torch
from torch.utils.data import Dataset

class GPTDatasetV1(Dataset):
    def __init__(self, txt, tokenizer, max_length, stride):
        self.input_ids = []
        self.target_ids = []

        token_ids = tokenizer.encode(
            txt, allowed_special={"<|endoftext|>"}
        )
        assert len(token_ids) > max_length, "최소 max_length+1 토큰 필요"

        for i in range(0, len(token_ids) - max_length, stride):
            input_chunk = token_ids[i:i + max_length]
            target_chunk = token_ids[i + 1:i + max_length + 1]
            self.input_ids.append(torch.tensor(input_chunk))
            self.target_ids.append(torch.tensor(target_chunk))

    def __len__(self):
        return len(self.input_ids)

    def __getitem__(self, idx):
        return self.input_ids[idx], self.target_ids[idx]

교안의 빈칸을 채우고 주석을 줄인 코드입니다. 아래 두 줄은 앞선 실습에서 만든 raw_text와 tokenizer를 사용합니다.

dataset = GPTDatasetV1(raw_text, tokenizer, max_length=4, stride=2)
print(len(dataset))
x, y = dataset[0]
print(x, y)
print(x.shape, y.shape)  # 각각 torch.Size([4])
단계무슨 일을 하나요?
빈 리스트 두 개입력 카드와 정답 카드를 같은 순서로 저장할 공간을 만듭니다.
tokenizer.encode전체 텍스트를 토큰 ID 리스트로 바꿉니다. 이 클래스는 문자열을 받으므로 먼저 encode합니다.
assert다음 토큰 정답까지 만들 수 있는 길이인지 확인합니다. 길이 4의 샘플에는 원본 토큰 최소 5개가 필요합니다.
range(..., stride)시작점 i를 움직이며 여러 샘플을 만듭니다. 불완전한 마지막 샘플은 만들지 않습니다.
torch.tensor와 append각 조각을 텐서로 바꾸고 리스트에 추가합니다. ID를 임베딩 벡터로 바꾸는 단계는 아닙니다.
i와 idx를 구분하세요.
i는 원본 토큰 줄에서의 시작점, idx는 만들어진 샘플 보관함의 번호입니다. 예를 들어 stride=2일 때 두 번째 샘플은 idx=1, 원본 시작점은 i=2입니다.

__getitem__에서는 입력·정답 모두 같은 idx를 씁니다. 정답을 한 칸 미는 작업은 이미 target_chunk를 만들 때 했습니다. 여기서 idx+1을 사용하면 다른 샘플의 정답을 꺼내 짝이 어긋납니다.

Dataset과 DataLoader: 지금 클래스는 샘플 한 쌍을 반환합니다. 다음 셀의 DataLoader가 여러 샘플을 배치로 묶습니다. 길이 4의 입력 한 개는 shape (4,)이고 배치 크기가 8이면 (8,4)가 됩니다.

샘플 수를 직접 확인하는 식

원본 토큰 수 N, 길이 L, 양의 stride S라면 교안의 샘플 수는 len(range(0, N-L, S))입니다. 예: N=9, L=4, S=2 → [0,2,4] → 3개입니다. N≤L이면 이 교안의 assert에서 먼저 멈춥니다.

원본 코드는 양의 max_length·stride를 전제로 합니다. 특히 stride=0은 range 오류를 일으킵니다. stride가 길이보다 크면 입력 창 사이에 건너뛰는 구간이 생길 수 있습니다.

06 · 세 메서드를 내 말로

__init__, __len__, __getitem__의 역할을 한 문장씩 설명하고, 왜 __getitem__에서 정답 idx를 +1 하지 않는지 덧붙이세요.

작성 후 비교할 해설

__init__은 샘플들을 준비하고, __len__은 샘플 개수를 알려주며, __getitem__은 요청한 샘플의 입력·정답을 꺼냅니다. 예: dataset[0]은 0번 입력과 0번 정답입니다. target_chunk가 이미 다음 토큰으로 이동되어 있으므로 같은 idx를 사용합니다.

import torch
from torch.utils.data import Dataset

# 다음 토큰 ID를 돌려주는 연습용 도구. 실제 BPE가 아닙니다.
class FixedTokenizer:
    def encode(self, txt, allowed_special=None):

# 여기에 GPTDatasetV1 클래스를 직접 작성하세요.

완료 기준: 새 커널에서 전체 실행 성공 + 위 검사를 모두 통과 + i와 idx의 차이 설명. 다운로드와 BPE 결과의 영향을 분리하기 위해 고정 도구를 사용합니다.
