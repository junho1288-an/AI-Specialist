1. 이번 셀이 만드는 것

파일 준비없으면 다운로드
→
raw_text문자열로 읽기
→
enc_text토큰 ID 리스트
→
x · y입력과 다음 토큰 정답

예를 들어 a b c d e라는 토큰 흐름이 있으면 x = a b c d, y = b c d e입니다. 이번 셀은 학습에 쓸 짝을 준비하며, 모델 학습은 아직 하지 않습니다.

2. 파일이 없을 때만 받습니다

import os
import requests

os.makedirs("datas", exist_ok=True)
if not os.path.exists("datas/the-verdict.txt"):
    url = (
        "https://raw.githubusercontent.com/rasbt/"
        "LLMs-from-scratch/main/ch02/01_main-chapter-code/"
        "the-verdict.txt"
    )
    file_path = "datas/the-verdict.txt"
    response = requests.get(url, timeout=30)
    response.raise_for_status()
    with open(file_path, "wb") as f:
        f.write(response.content)

with open("datas/the-verdict.txt", "r", encoding="utf-8") as f:
    raw_text = f.read()
코드역할
makedirs(..., exist_ok=True)datas 폴더 만들기. 같은 폴더가 이미 있어도 괜찮습니다.
if not ...exists(...)파일이 없을 때만 다운로드. 이미 있으면 이 if 블록을 건너뜁니다.
requests.get(..., timeout=30)HTTP로 파일 요청. 서버 연결·응답을 무한정 기다리지 않게 합니다. 전체 다운로드가 반드시 30초 안에 끝난다는 뜻은 아닙니다.
raise_for_status()404 등 HTTP 오류 응답이면 예외를 내고 저장 전에 멈춥니다.
"wb"와 response.content받은 bytes를 파일에 바이너리 쓰기. w는 쓰기, b는 바이너리입니다.
"r", encoding="utf-8"저장한 파일을 UTF-8 문자열로 읽기. f.read()가 raw_text를 만듭니다.

예시: 처음 실행하면 다운로드 후 읽고, 두 번째 실행에서는 파일이 있으므로 다운로드를 건너뛰고 읽습니다. 마지막 with open은 if 바깥에 있어 두 경우 모두 실행됩니다. with는 블록을 나갈 때 파일을 닫아 줍니다.

datas는 어디에 생길까요?
상대 경로는 Python 커널의 현재 작업 폴더 기준입니다. print(os.getcwd())로 확인하세요. 교안 폴더에서 실행한다면 보통 그 안의 datas를 사용합니다.

근거: Requests 공식 Quickstart, Python 파일 읽기·쓰기.

3. 글자 수와 토큰 수는 다릅니다

# 첫 실습 셀에서 tokenizer를 먼저 만들어 두어야 합니다.
enc_text = tokenizer.encode(raw_text)
print(len(enc_text))
enc_sample = enc_text[50:]

raw_text는 문자열이고 enc_text는 토큰 ID 리스트입니다. 따라서 len(enc_text)는 전체 토큰 개수입니다. 어휘표 크기나 글자 수가 아닙니다.

예시: "Hello,"는 6글자지만 앞 수업의 GPT-2 인코딩에서는 [15496, 11], 즉 2토큰입니다.

enc_text[50:]는 인덱스 50부터 끝까지입니다. 0부터 세므로 앞의 50개 토큰을 건너뛰고 51번째 토큰부터 가져옵니다. ID가 50인 토큰을 찾는 것이 아닙니다. 이번 실습에서 샘플 시작점을 고른 것이며 GPT의 필수 규칙은 아닙니다.

4. y는 왜 양쪽에 +1일까요?

context_size = 4
x = enc_sample[:context_size]       # [0:4]
y = enc_sample[1:context_size + 1]  # [1:5]

슬라이싱 [시작:끝]은 시작 포함, 끝 제외입니다. x는 인덱스 0~3, y는 1~4에서 각각 4개를 가져옵니다. y의 시작·끝을 함께 옮겨야 길이가 같습니다.

이해용 ID 예시: enc_sample = [10, 20, 30, 40, 50]
인덱스01234
원본 ID1020304050
x10203040—
y—20304050

세로 칸은 원본의 위치를 나타냅니다. 학습 쌍으로 나란히 맞추면 x = [10, 20, 30, 40], y = [20, 30, 40, 50]입니다. 숫자 크기에 규칙이 있는 게 아니라, 원본에서 다음 위치의 ID를 정답으로 삼습니다.

직접 길이를 바꿔 보기

x = sample[:context_size] → [10,20,30,40]

y = sample[1:context_size+1] → [20,30,40,50]

고정된 연습용 ID 리스트를 자르는 시각화입니다. Python이나 실제 토크나이저를 실행하지 않습니다.

다음 토큰 예측에서는 현재까지의 내용을 참고해 다음 토큰을 맞힙니다. 예를 들어 첫 위치는 [10] → 20, 마지막 위치는 [10,20,30,40] → 50입니다. 뒤쪽 정답을 미리 못 보게 하는 Causal mask는 모델 쪽에서 적용합니다.

정답도 원문에서 가져오므로 사람이 별도 정답을 붙이지 않는 Self-supervised learning(자기지도학습)의 예입니다.

교안에 저장된 출력과 비교
5145
x: [290, 4920, 2241, 287]
y:      [4920, 2241, 287, 257]

5145는 저장된 실행의 전체 토큰 수입니다. x의 두 번째 값 4920이 y의 첫 값이고, y 끝의 257은 원본의 다음 토큰입니다. 이 HTML에서 새로 다운로드하거나 계산한 값은 아닙니다. 원문과 인코딩에 따라 결과는 달라질 수 있습니다.

슬라이싱: Python 리스트 공식 설명. 다음 토큰 예측: Hugging Face 공식 안내.

5. 설명을 가리고 시험 보기

1~5번은 브라우저에서 답을 확인합니다. 6번은 직접 비교, 7번은 노트북 실기입니다. 답은 자동 저장·전송되지 않습니다.

01 · 첫 번째 빈칸

y = enc_sample[????:context_size + 1]

시도 후 정답·해설

1. 예: [10,20,30][1:]은 [20,30]입니다.

02 · 두 번째 빈칸

y = enc_sample[1:context_size + ????]

시도 후 정답·해설

1. 길이 4가 필요하면 [1:5]입니다. [1:4]는 원소가 충분해도 3개뿐입니다.

03 · 토큰 개수

“len(enc_text)는 원문에 있는 글자의 개수다.”

시도 후 정답·해설

X. 예: GPT-2에서 "Hello,"는 6글자, 2토큰입니다.

04 · 이미 파일이 있다면?

“이 코드에서는 파일이 이미 있으면 다운로드를 건너뛰고 파일 읽기를 실행한다.”

시도 후 정답·해설

O. 예: 두 번째 실행에서도 raw_text = f.read()는 수행됩니다.

05 · 끝 인덱스는 포함할까?

sample = [10, 20, 30, 40, 50]
context_size = 4
y = sample[1:context_size + 1]
print(y[-1])

시도 후 정답·해설

50. 결과 y는 [20,30,40,50]이고, [-1]은 마지막 원소입니다.

06 · 50은 무슨 뜻일까요?

enc_text[50:]의 50이 무엇인지, y에 정답이 어떻게 생기는지 각각 한 문장으로 적어 보세요.

작성 후 비교할 해설

50은 ID 값이 아니라 시작 인덱스입니다. 앞의 50토큰을 건너뜁니다. y는 원본에서 다음 위치 토큰들을 가져와 만든 정답입니다.

예: a b c d e에서 입력 a b c d에 대한 정답은 b c d e입니다. e는 임의로 만든 값이 아닙니다.

07 · 빈 노트북 실기

설명을 닫고 practice/day-01/next-token-pairs.ipynb에 작성하세요. 폴더와 파일은 직접 만듭니다. 예상 5분, 다운로드가 필요 없는 과제입니다.

  1. sample = [7, 12, 4, 9, 2, 18], context_size = 3을 준비합니다.
  2. 변수 context_size를 사용해 x와 한 칸 뒤 y를 만듭니다.
  3. 실행 전에 예상 x·y를 주석으로 적고, 실제 값을 출력합니다.
  4. 두 길이가 context_size와 같은지 검사합니다.
  5. context_size를 5로 바꿔 다시 실행하고, 왜 원본 토큰이 최소 길이+1개 필요한지 설명합니다.
시도 후 모범 코드
sample = [7, 12, 4, 9, 2, 18]
context_size = 3
# 예상 x: [7, 12, 4], y: [12, 4, 9]
x = sample[:context_size]
y = sample[1:context_size + 1]
print(x, y)
assert len(x) == len(y) == context_size
assert x[1:] == y[:-1]

길이 5로 바꾸면 x는 [7,12,4,9,2], y는 [12,4,9,2,18]입니다. 마지막 입력의 다음 토큰까지 정답으로 필요해 총 6개를 사용합니다. 완료 기준: 새 커널 전체 실행 + 두 길이 확인 + +1의 이유 설명.

초기화는 1~5번 답과 피드백을 지웁니다. 6번 설명은 유지합니다. 실제 제출·숙달 기록은 에이전트와 확인합니다.
