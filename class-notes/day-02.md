### Python 질문: with open(...) as f

- **뜻**: 파일을 열어 들여쓴 코드에서 사용하고, 블록을 벗어나면 자동으로 닫는다. 블록 안에서 오류가 발생해도 파일을 닫는 정리 작업을 한다. 오류를 자동으로 해결하거나 무시하는 것은 아니다.
- `open("datas/the-verdict.txt", "r", encoding="utf-8")`: 해당 경로의 파일을 읽기 모드(r)로 열고 UTF-8 방식으로 글자를 해석한다. 상대 경로는 현재 작업 폴더 기준이다.
- `as f`는 열린 파일 객체를 f라는 이름으로 받는 부분이다. `f.read()`는 파일 내용을 문자열로 읽고, `raw_text = ...`는 그 문자열을 변수에 저장한다.
- **예시**:

```python
# 파일 내용이 Hello라고 가정
with open("datas/the-verdict.txt", "r", encoding="utf-8") as f:
    raw_text = f.read()  # 파일에서 문자열 읽기

print(raw_text)  # Hello: 읽어 둔 문자열은 계속 사용 가능
print(f.closed)  # True: 파일은 이미 닫힘
```

**기억하기**: 들여쓴 부분이 with의 범위다. 범위 밖에서도 raw_text는 사용할 수 있지만 닫힌 f에서 다시 read()하면 오류가 난다. f라는 이름은 file 등 다른 이름으로 바꿔도 된다.

### Python 질문: from ... import ...

- **문법**: `from 모듈경로 import 이름1, 이름2`. 해당 모듈에서 제공하는 이름을 현재 코드에서 바로 쓸 수 있게 가져온다. `torch.utils.data`는 점으로 구분한 모듈 경로이고, `Dataset`·`DataLoader`는 거기서 제공하는 클래스 이름이다.
- **예시**:

```python
import torch
loader = torch.utils.data.DataLoader(dataset, batch_size=2)

# 같은 클래스를 짧은 이름으로 사용
from torch.utils.data import Dataset, DataLoader
loader = DataLoader(dataset, batch_size=2)
```

- **장점**: 긴 경로를 반복하지 않아 코드가 짧아지고, 이 코드에서 사용할 클래스가 무엇인지 import 줄에 드러난다. `class GPTDatasetV1(Dataset):`처럼 상속할 때도 간결하다. 속도나 모델 성능을 높이기 위한 문법은 아니다.
- **주의**: 이 줄만으로 `torch`라는 이름까지 생기지는 않는다. `torch.tensor(...)`도 쓰려면 `import torch`가 별도로 필요하다. 서로 다른 모듈의 같은 이름이 충돌하면 전체 경로를 쓰거나 `as`로 별명을 붙인다. Dataset은 샘플을 제공하고 DataLoader는 이를 배치로 묶는다.

### PyTorch 질문: batch는 무엇일까?

- **샘플**은 학습 예제 하나, **배치(batch)**는 한 번에 꺼내는 샘플 묶음이다. 교안에서는 입력·정답 쌍이 샘플 하나다.
- **예시**: 샘플 5개를 batch_size=2로 꺼내면 2개·2개·1개다. drop_last=True면 마지막 1개 묶음을 제외한다.
- 길이 4의 샘플을 2개 묶으면 입력과 정답 각각 shape `(2,4)`다. batch_size는 2, max_length는 4이며 토큰 총수 8과 구분한다.
- [학생·이미지·토큰 예시로 배우는 배치 HTML 수업](../lessons/0024-day02-batch.html): 직접 묶어 보는 그림과 확인 문제를 포함한다.

### PyTorch 질문: Embedding(6,3)에 [2,3,5,1]을 넣으면?

- **6**은 어휘 ID 종류 수(0~5), **4**는 이번 입력의 ID 개수, **3**은 각 ID에 대응하는 실수 벡터의 길이다. 이번 입력 shape `(4,)`에는 별도의 배치 축이 없다.
- **예시**: 입력 `[2,3,5,1]`은 `weight[2]`, `weight[3]`, `weight[5]`, `weight[1]`을 순서대로 꺼낸다. 표는 `(6,3)`, 출력은 `(4,3)`이다. 같은 ID를 반복하면 같은 표의 같은 행을 여러 번 가져온다.
- Embedding의 역할은 ID를 학습 가능한 벡터에 연결하는 것이다. weight가 바로 그 표이며, 처음에는 무작위 초기화된다. 조회만으로 표가 학습되거나 ID가 벡터 값으로 덮어써지지는 않는다.
- [표의 행을 직접 눌러 보는 HTML 그림 수업](../lessons/0025-day02-embedding-lookup.html)에 실제 코드로 얻은 weight와 출력 행을 나란히 표시했다.

### 개념 질문: LoRA와 파인튜닝

- **LoRA = Low-Rank Adaptation(저랭크 적응)**. 이미 학습된 모델을 적은 수의 학습 파라미터로 조정하는 **PEFT(Parameter-Efficient Fine-Tuning, 파라미터 효율적 미세조정)** 방법이다.
- **Fine-tuning(파인튜닝, 미세조정)**은 사전학습 모델을 특정 데이터·작업에 맞게 추가 학습하는 것이다. LoRA는 파인튜닝을 효율적으로 하는 기법이지, 분류·챗봇처럼 특정 작업의 이름은 아니다.
- 원래 큰 가중치 W는 고정하고 작은 행렬 A·B를 학습해 만든 변화량을 더한다: `W_new = W + ΔW`, `ΔW = B @ A`(스케일 계수 생략). rank는 이 변화량을 표현할 작은 차원이다. 실제 학습 대상에 분류 헤드 등을 추가하는 설정도 가능하다.
- **예시**: 1000×1000 가중치 하나 전체를 학습하면 100만 개가 대상이다. LoRA rank=8이면 A(8×1000), B(1000×8)의 총 16,000개를 학습한다. 이 가중치 행렬 하나 기준의 비교이며 모델 전체 비용이 그대로 같은 비율로 줄어든다는 뜻은 아니다.

출처: [LoRA 원 논문](https://arxiv.org/abs/2106.09685). 교안 Chapter 6의 LoRA 분류 파인튜닝과 연결되는 보충 설명이다.

### 개념 질문: RLHF와 DPO

- **RLHF = Reinforcement Learning from Human Feedback(인간 피드백 기반 강화학습)**. 사람의 평가·선호를 이용해 모델이 더 선호되는 답을 하도록 조정하는 방식이다. 대표 흐름은 좋은 답 예시로 미세조정 → 답변 선호로 보상 모델 학습 → 보상 모델의 점수를 이용한 강화학습이다.
- **DPO = Direct Preference Optimization(직접 선호 최적화)**. 같은 질문의 더 선호한 답(chosen)·덜 선호한 답(rejected) 쌍으로 언어 모델을 직접 조정한다. 전통적인 보상 모델 기반 RLHF와 달리 별도의 보상 모델을 학습하거나 강화학습 루프를 돌리지 않는다. 기본 DPO는 고정한 기준 모델(reference model)과 비교한다.
- **같은 예시**: 질문 ‘배치가 뭐야?’에 A ‘한 번에 처리하는 샘플 묶음이야. 5개를 2개씩 묶으면 2·2·1개야’, B ‘그냥 묶음’이 있고 사람이 A를 선호했다고 하자. 전통 RLHF는 이런 평가로 채점할 보상 모델을 먼저 배우고 그 점수를 높이도록 모델을 학습한다. DPO는 이 A·B 쌍에서 A를 상대적으로 더 선호하도록 직접 학습한다.
- 교안 `Chapter_7_Exercise_Follow_Instructions_dpo.ipynb`의 `prompt`, `chosen`, `rejected`는 이 데이터 구조다. reference와 학습 모델에서 두 답의 로그확률을 비교하는 손실을 사용한다. 선호하는 답이 항상 객관적 정답이라는 뜻은 아니다.

### Attention 전체 흐름: Q·K·V는 왜 필요한가?

- **Q(Query, 질의)**는 찾는 특징, **K(Key, 검색 단서)**는 비교할 특징, **V(Value, 전달 정보)**는 실제 가져올 내용이다. 같은 입력에 서로 다른 학습 행렬을 적용해 세 벡터를 만든다.
- Q·K 내적 → 미래 마스크 → 스케일 조절·softmax로 **참고 비율**을 만들고, 그 비율로 V들을 섞어 **문맥 벡터**를 만든다. Attention이 바로 단어를 출력하는 것은 아니며, 뒤의 GPT 출력층이 다음 토큰을 예측한다.
- **예시:** 참고 비율 [0.8,0.2], V₁=[10,0], V₂=[0,10]이면 출력은 [8,2]. 비율을 그대로 두고 V만 바꾸면 출력 내용이 바뀐다.
- Chapter 3 셀 2의 Your journey… 입력은 tokenizer 결과가 아니라 직접 제공한 3차원 예시 벡터다. [시각화 수업](../lessons/0026-day02-attention-journey.html)에서 토큰별 계산·미래 차단·V 변경을 실험하고 [복습 카드](../reference/day02-attention-journey.html)로 확인한다. 근거: 교안 PDF 104~120쪽·Chapter 3 셀 1~5. 실제 이해·독립 구현은 아직 미확인이다.

#### Q·K·V의 “각각의 행렬”이란?

- 가중치 표 세 개 `W_query`, `W_key`, `W_value`가 따로 있다는 뜻이다. 같은 입력 벡터를 서로 다른 세 표로 조합하여 Q·K·V를 만든다.
- **예시:** x=[1,2,3]에 Q용 조합법 [첫째, 둘째+셋째], K용 [둘째, 첫째+셋째], V용 [첫째+둘째, 셋째]를 적용하면 Q=[1,5], K=[2,4], V=[3,3]이다. 계산을 쉽게 만든 보충 예시다.
- 다른 토큰에도 이 세 표를 그대로 공유한다. Q용 표를 모든 토큰에 적용하고, K용·V용 표도 각각 모든 토큰에 적용한다. 학습 중 세 표의 숫자가 갱신된다. [수업의 숫자 표 설명](../lessons/0026-day02-attention-journey.html#roles)에도 보완했다.

### Attention Map 숫자 계산: Your·journey

- Map의 행은 Q를 내는 위치, 열은 참고할 K·V 위치다. Q·각 K 내적 → 미래를 `-∞`로 덮기 → √d_k로 나누기 → 행별 softmax가 Map의 비율이다. 예제 Q·K 길이는 2여서 √2로 나눈다.
- **예시:** journey의 앞 두 점수 [0.165519,0.260194]를 남기고 미래 4개는 `-∞`로 바꾼다. √2로 나누면 [0.117039,0.183985,-∞,-∞,-∞,-∞]. softmax 결과 [0.483270,0.516730,0,0,0,0]이 Map의 journey 행이다. [journey,Your] 칸은 약 0.483이다.
- Your는 자기 자신만 볼 수 있으므로 첫 행은 [1,0,0,0,0,0]. V는 비율 계산 후 가중합에 쓴다. [표 바로 위 대표 계산](../lessons/0026-day02-attention-journey.html#map-worked-example)에 QKV 숫자·전체 6열 점수·mask·분모·Map 좌표까지 추가했다.

### Map의 자기 자신은 왜 항상 1이 아닌가?

- Map은 내적 원점수가 아니라 mask·scale·softmax 뒤의 참고 비율이다. **예시:** Your·Your 원점수는 약 0.311080이지만, 미래를 가리면 자기 하나만 남아서 비율이 1이다.
- journey는 Your·자기 자신 두 대상에 비율을 나눠 주므로 [0.483,0.517]이다. 0.483은 거의 반반이며 자기 비율보다 낮다. 같은 점수라면 후보 하나는 1, 둘은 0.5씩, 셋은 1/3씩이다.
- 자기 토큰이라도 Q와 K는 서로 다른 W로 만든 벡터라 같지 않을 수 있고, 내적이 1로 고정되지 않는다. V는 정해진 비율로 가져올 내용이다. 이 예시는 랜덤 W이므로 수치를 실제 단어의 의미적 관계로 단정하지 않는다. [문서 보완](../lessons/0026-day02-attention-journey.html#map-reading).

### Q·K·V를 도서관으로 비유하면

- Q는 후보를 담은 책이 아니라 **찾고 싶은 내용을 적은 검색어**, 각 K는 **각 책의 검색용 단서**, 각 V는 **그 책에서 가져올 내용**에 가깝다. K가 Q 안에 들어 있는 것은 아니다.
- **예시:** journey 위치의 Q는 Your·journey의 K를 비교해서, 두 위치의 V를 각각 약 48.3%·51.7% 섞는다. starts 이후 K와 비교한 점수는 미래 마스크로 `-∞`가 되어 참고 비율이 0이다.
- `-∞`는 책이 없다는 뜻보다 **책은 있지만 지금은 열람 금지**라는 비유가 맞다. 실제 전체 계산에서는 미래 K와의 점수도 구한 다음 mask로 덮는다. 후보 허용 여부는 Q 자체가 아니라 인과적 마스크가 정한다.

### Attention Map 단계별 비교

- [3단계 지도 비교](../lessons/0026-day02-attention-journey.html#map-comparison)를 추가했다. QKᵀ 원점수 → mask·√2 스케일링 후(softmax 직전) → softmax 결과(V 가중합 직전)를 같은 행·열로 비교한다.
- **예시:** journey→Your 칸은 0.165519 → 0.117039 → 0.483270. Your→journey는 0.347907 → -∞ → 0이다. 마지막 비율 행렬에 V를 곱하면 문맥 벡터가 되며 토큰×토큰 지도와 shape가 달라진다.

### Q·K·V 차원과 가중치 크기 구분

- Q·K·V의 벡터 길이가 입력 차원의 두 배라는 규칙은 없다. Chapter 3 단일 헤드 예시는 d_in=3, d_out=2로 설정해서 한 토큰의 3개 숫자를 각각 2개 숫자로 변환한다.
- **예시:** nn.Linear(3,2,bias=False)의 weight는 (2,3)이고 계산은 x @ weight.T이다. (6,3) 입력 → 각 Q·K·V는 (6,2), 배치 포함 (2,6,3) → 각 (2,6,2). 세 벡터를 하나로 합쳐 6차원이라고 부르지 않는다.
- 입력 3 → 출력 2 설정과 가중치의 3×2 계산 방향을 구분한다. d_out은 설계로 정하며 2·4·8 등 다른 폭도 가능하다. 일반 attention에서는 Q·K의 길이는 내적을 위해 같아야 하지만 V 길이는 다를 수 있다. 현재 교안 구현은 Q·K·V 모두 d_out으로 맞춘다.

### 일반 LLM의 Attention Map이 2차원인 이유

- 사용자는 d_out=2 설정이 아니라 Map이 가로×세로인 이유를 질문했다. **벡터의 특징 수**와 **배열 축 개수**를 구분한다. Q·K가 토큰당 수십·수백 개 특징을 가져도 한 샘플·한 헤드의 Map은 (토큰 수, 토큰 수)의 2축 표다.
- **예시:** 토큰 6개, 헤드별 Q·K 특징 64개이면 Q=(6,64), Kᵀ=(64,6), QKᵀ=(6,6)이다. 특징 64개를 곱해 더한 점수 하나가 토큰 쌍마다 나와서 표의 한 칸이 된다. 2차원 Map이라는 말이 Q·K·V에 숫자가 2개씩 있다는 뜻은 아니다.
- 행은 질문하는 위치, 열은 참고하는 위치이며 V는 표의 세 번째 축이 아니다. 비율 (6,6) @ V (6,64) → 문맥 벡터 (6,64). 여러 배치·헤드를 함께 저장하면 Map 전체 shape는 (B,H,T,T)의 4축일 수 있으며 보통 그림은 그중 한 샘플·한 헤드를 보여 준다.

### Python·PyTorch의 @ 연산자: 행렬 곱셈

- `A @ B`는 행렬 곱셈이다. 왼쪽 행과 오른쪽 열의 같은 위치 숫자를 곱한 뒤 더해 결과 한 칸을 만든다. 두 행렬은 `(m,n) @ (n,p) → (m,p)`로 안쪽 크기가 같아야 한다.
- **예시:** A=[[1,2],[3,4]], B=[[5,6],[7,8]]이면 A@B=[[19,22],[43,50]]. 첫 칸은 1×5+2×7=19다. 반면 A*B는 같은 칸끼리 곱하는 원소별 곱 [[5,12],[21,32]]이다.
- Attention의 Q@K.T는 각 Q와 각 K의 내적 점수를 표로 모으는 계산이다. Q=(6,64), K.T=(64,6) → 점수=(6,6). 비율 A=(6,6) @ V=(6,64)는 각 행의 비율로 V들을 가중합해 (6,64) 문맥 벡터를 만든다. 배치가 있으면 마지막 두 축으로 행렬 곱을 하고 앞 축은 배치 규칙을 따른다.

### 배치가 있는 3축 텐서의 @ 계산

- `(2,6,2) @ (2,2,6)`에서 맨 앞 2는 배치 수다. 배치 0끼리 `(6,2)@(2,6)`, 배치 1끼리 같은 계산을 각각 해서 결과 `(6,6)` 두 개를 쌓는다. 배치끼리는 섞이지 않는다.
- **예시:** 한 배치의 Q 첫 행=[1,2], K의 6개 행=[1,0],[0,1],[1,1],[2,0],[0,2],[2,2]이면 첫 점수 행=[1,2,3,2,4,6]. 각 Q행마다 6개의 K와 내적해 총 6×6 점수를 만든다.
- `(2,6,6) @ (2,6,2)`도 배치별 `(6,6)@(6,2)`다. 예를 들어 비율의 한 행=[0.8,0.2,0,0,0,0], V 첫 두 행=[10,0],[0,10]이면 출력 한 행=[8,2]. 이런 2개 숫자짜리 행을 6개 만들고, 배치 두 개를 모으면 `(2,6,2)`다.
- 사용자는 “앞 배치는 두고 마지막 두 축을 계산한 결과가 배치 수만큼 있다”고 설명했다. 현재처럼 양쪽 배치 크기가 같은 경우 맞다. 예: `(2,6,2)@(2,2,6)`은 같은 배치 번호끼리 `(6,2)@(2,6)`을 두 번 수행한다. 배치 수를 결과 숫자에 곱하는 것은 아니다. 이 설명은 배치별 계산 구분의 즉시 이해 증거이며 지연 인출·독립 구현은 별도 확인한다.

### 왜 Causal Attention이라고 부르는가?

- **Causal Attention = 인과적 어텐션**. 현재 위치의 출력이 미래 토큰에 의존하지 않도록, 현재·이전 위치만 참고하게 하는 Attention이다. 여기서 인과적이라는 말은 시간·순서에 따른 정보 흐름 제한을 뜻하며 현실의 인과관계를 추론한다는 뜻은 아니다.
- **예시:** 입력 `Your journey starts with one step`에서 journey 위치는 Your·journey만 참고한다. 이 위치가 다음 토큰 starts를 예측할 때, 입력의 starts를 미리 참고하면 정답을 보는 셈이므로 금지한다.
- 코드에서는 미래 위치의 점수를 `-∞`로 덮고 softmax를 적용해 해당 비율을 0으로 만든다. 학습에서 여러 위치를 동시에 계산해도 미래 정보가 새지 않게 하며, 생성 때 앞의 토큰만 이용하는 조건과 맞춘다.

### Causal Mask 생성과 register_buffer

- `ones(T,T)`로 모두 1인 표를 만들고 `triu(...,diagonal=1)`로 주대각선 위쪽만 1로 남긴다. 여기서 1은 참고 허용이 아니라 **미래 차단 표시**다.
- **예시:** T=4의 journey 행은 `[0,0,1,1]`. Your·journey는 허용하고 starts·with는 차단한다. `mask.bool()`의 True 위치를 forward의 masked_fill_로 -∞로 바꾸면 softmax 후 비율이 0이다.
- `register_buffer('mask', 표)`는 표를 `self.mask`라는 비학습 상태로 등록한다. 이 표는 학습 파라미터가 아니지만 모델의 device 이동에 따라가고 기본 설정에서 state_dict에 포함된다. 등록 자체가 점수를 가리는 것은 아니다. [코드·그림 수업](../lessons/0027-day02-causal-mask-buffer.html) 참조.

### W_key(x)는 여러 토큰을 어떻게 한꺼번에 바꾸는가?

- `nn.Linear(d_in,d_out)`는 입력의 마지막 축만 바꾸고 배치·토큰 축을 유지한다. `x=(B,T,d_in)` → keys·queries·values 각각 `(B,T,d_out)`. 같은 W_key를 모든 배치·모든 토큰에 공유하며 토큰끼리 합치지 않는다.
- **예시:** bias=False, W_key.weight=[[1,0,1],[0,1,1]]이면 각 입력 [a,b,c] → key=[a+c,b+c]. 한 배치 x=[[1,2,3],[4,5,6],[7,8,9]]는 keys=[[4,5],[10,11],[16,17]]이 된다. 배치 두 개면 (2,3,3) → (2,3,2). PyTorch 2.5.1 실제 실행으로 확인했다.
- 계산은 `x @ W_key.weight.T`(bias가 있으면 더함). Q·V도 동일한 모양으로 계산하되 각자 다른 가중치를 쓴다. 토큰 사이 정보 혼합은 그 뒤 QK 점수·V 가중합에서 일어난다. PyTorch가 호출하는 메서드 이름은 `forward(self,x)`이며 `__forward__`가 아니다.

### keys.transpose(1,2)의 인자는 축 번호

- `tensor.transpose(dim0,dim1)`은 지정한 두 축을 맞바꾼다. 축 번호는 0부터 시작한다. keys=(B,T,D)에서 0은 배치, 1은 토큰, 2는 특징이므로 transpose(1,2)는 (B,D,T)를 만든다. 숫자 1·2는 차원의 크기나 반복 횟수가 아니다.
- **예시:** 한 배치 keys=[[1,2],[3,4],[5,6]]의 (3,2)를 전치하면 [[1,3,5],[2,4,6]]의 (2,3)이다. 배치 2개이면 전체 (2,3,2) → (2,2,3). PyTorch 실제 출력으로 확인했다.
- Q의 각 행과 K의 각 토큰을 내적하려고 K의 토큰 벡터를 열에 배치한다. queries=(2,6,2) @ keys.transpose(1,2)=(2,2,6) → attn_scores=(2,6,6). 결과 [b,i,j]는 같은 배치에서 Q_i·K_j이다. 마지막 두 축 교환은 transpose(-2,-1)로도 쓴다. 헤드 축이 추가된 (B,H,T,D)에서는 transpose(2,3) 또는 (-2,-1)을 사용한다.

### CausalAttention.forward의 전체 shape 흐름

- 일반식: 입력 x=(B,T,d_in) → keys·queries·values 각각 (B,T,d_out) → K 전치 (B,d_out,T) → 점수 (B,T,T) → mask·softmax·dropout 후에도 (B,T,T) → V 가중합 (B,T,d_out).
- **예시:** B=2, T=6, d_in=3, d_out=2이면 x=(2,6,3), QKV 각각 (2,6,2), scores·weights=(2,6,6), 최종 context_vec=(2,6,2). 배치마다 토큰 6개 각각에 2개 숫자의 문맥 벡터가 나온다.
- 저장 mask는 (context_length,context_length), 자른 mask는 (T,T)이며 배치 축에 공유되어 점수를 가린다. keys.shape[-1]=d_out으로 √d_out 스케일링하며 shape는 유지된다. softmax dim=-1은 참고 대상 토큰 축이다. 최종 벡터는 다음 토큰 ID나 어휘 확률이 아니다.
